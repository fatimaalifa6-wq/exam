# Smart Exam Grader (نسخة مُصلَحة)

نفس فكرة المشروع الأصلي بالضبط: إنشاء اختبار، طباعته، تصوير ورقة إجابة
الطالب، وتصحيحها تلقائيًا بتقنية OMR. هذه النسخة تحتفظ بنفس الآلية لكنها
تعالج مشاكل المحاذاة والقراءة والأمان التي اكتُشفت أثناء المراجعة.

## أهم التعديلات عن النسخة الأصلية

### 1. تصحيح دوران EXIF (`omr_grader.py`)
الجوالات غالبًا تحفظ الصورة "مستقيمة" بصريًا لكن **بيانات البكسل الخام
تبقى مدوّرة**، والاتجاه الصحيح يُحفظ فقط كوسم وصفي (EXIF tag). الكود
الأصلي يستخدم `cv2.imread()` الذي **يتجاهل** هذا الوسم تمامًا، فتُقرأ
الصورة بزاوية خاطئة بالكامل رغم أنها تبدو سليمة عند فتحها بأي برنامج
عادي. الحل: قراءة الصورة أولًا عبر Pillow وتطبيق
`ImageOps.exif_transpose()` قبل تمريرها لـ OpenCV (دالة `load_image`
الجديدة).

### 2. كشف أكثر موثوقية للعلامات السوداء (`find_corner_markers`)
الكود الأصلي يختار أي 4 بقع داكنة "متطرفة الموضع" في الصورة كاملة، بدون
التأكد أنها فعلاً العلامات الأربع المطبوعة (قد يلتقط ظلًا أو حافة طاولة
داكنة بالخطأ). أضفنا تحققًا: العلامات الأربع الحقيقية متطابقة الحجم
فعليًا على الورقة، فلو تفاوتت مساحات الأربع بقع المختارة بشكل كبير
(أكثر من 4 أضعاف بين الأكبر والأصغر)، تُرفض النتيجة وينتقل النظام
للطريقة الاحتياطية التالية بدل الاعتماد على محاذاة خاطئة بثقة زائفة.

### 3. الإفصاح عن مستوى الثقة في النتيجة
النتيجة الآن تحمل حقل `alignment_method` (`markers` /
`document_contour` / `resize_fallback`) و`low_confidence`. إذا لم
تُكتشف العلامات الأربع بثقة، تظهر رسالة تحذير واضحة في صفحة النتيجة بدل
عرض درجة "نهائية" دون أي إشارة لاحتمال عدم الدقة.

### 4. تحقق حقيقي من نوع الملف المرفوع (`app.py`)
الكود الأصلي يتحقق فقط من **امتداد اسم الملف** (`.jpg` مثلًا)، وهذا يمكن
خداعه بسهولة بإعادة تسمية أي ملف. الآن يُفتح الملف فعليًا عبر
`PIL.Image.verify()` للتأكد أنه صورة صالحة قبل تمريره لأي معالجة.

### 5. مفتاح جلسة عشوائي بدل قيمة ثابتة
`SESSION_SECRET` غير المضبوط كان يتحول سابقًا لنص ثابت معروف
(`"local-development-secret"`) في كل نشر. الآن يُنشأ مفتاح عشوائي تلقائيًا
عند التشغيل إن لم يوجد المتغير، بدل الاعتماد على القيمة الافتراضية
القابلة للتخمين.

### 6. تنظيف `requirements.txt`
- حذف `opencv-python` المكرر مع `opencv-python-headless` (وجودهما معًا
  يثبت مكتبات واجهة رسومية غير ضرورية على سيرفر ويسبب تعارضات محتملة).
- حذف `pymupdf` غير المستخدم في أي من الملفات.

## ما لم يتغيّر

- `omr_layout.py` و`exam_generator.py`: نفس منطق التخطيط والتوليد الأصلي
  بدون تعديل — كانا يعملان بشكل صحيح.
- تدفق الاستخدام نفسه تمامًا: إنشاء → طباعة → تصوير → تصحيح تلقائي.

## قيود ما زالت قائمة (لم تُعالج في هذه الجولة)

- لا يوجد تصحيح لدوران **محتوى الصورة** نفسه إذا صُوّرت الورقة وهي
  مقلوبة فعليًا (180° أو بزاوية كبيرة) — فقط دوران EXIF الوصفي مُعالَج.
- لا يوجد مصادقة/صلاحيات على أي مسار — أي شخص يعرف `exam_id` يقدر يرفع
  صورة للتصحيح أو يحمّل نسخة الاختبار الفارغة.
- التخزين لا يزال ملفات JSON مسطحة بدون قفل تزامن.

## التشغيل

```bash
pip install -r requirements.txt
python main.py
```

يعمل التطبيق على المنفذ `5000`.

## ملاحظات التصوير (كما في النسخة الأصلية)

- استخدمي ورقة A4 غير مطوية.
- صوّري الصفحة كاملة من أعلى وبإضاءة متوازنة.
- تأكدي من ظهور العلامات الأربع الموجودة في زوايا الورقة.
- يجب تظليل دائرة واحدة فقط لكل سؤال بقلم داكن.
